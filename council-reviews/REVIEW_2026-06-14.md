# Council Review — the-council (2026-06-14)

**Target:** `github.com/adnanraf1q/the-council` @ `main` (self-review, unlimited findings)
**Stated goal:** portable, machine-agnostic Claude Code skills; one shareable source of truth across machines, accounts, and teams.

## Executive summary

**Verdict: invest.** Solid framework for managing and distributing portable instructions, but removing the finding caps turned a strategic advisory panel into a wordy, expensive linter. Restoring caps is the top action, then end-to-end CI tests for prompt regressions, then data-privacy warnings.

| 1 | Restore finding limits (caps) to the prompt | HIGH | quick-win | Prevents unbounded token usage, keeps reports focused, avoids output-token truncation. | Open |

## Engineering panel

### Architect

*"Two copies of the same prompt — because nothing says 'single source of truth' like maintaining it twice."*

**LOW · quick-win** — Prompt instructions duplicated
`council/SKILL.md:9-69` · `PROMPT.md:10-68`
The panel rules live in two files that must be hand-synced; they will drift the moment someone edits one and forgets the other.

**LOW · —** — Directory path stutter
`the-council/council/`
Cosmetic redundancy in the path. Noted for cleanliness; not worth a rename.

### Security reviewer

*"We read whatever the repo tells us to. What could a repo possibly tell us to do?"*

**MED · strategic** — Prompt-injection exposure
`council/SKILL.md:18`
The council reads files from arbitrary target repos; malicious comments or strings could carry instructions that override the model's own.

**LOW · quick-win** — Local plugin install runs code
`README.md:74`
`agy plugin install .` (Option E) executes code on the user's machine; the README should tell users to audit a plugin before installing.

### Performance, infra & scale

*"Unlimited findings on an LLM that charges per token — bold cost-control strategy."*

**HIGH · quick-win** — Unbounded token consumption
`council/SKILL.md:22` · `PROMPT.md:55`
Removing finding caps lets the model emit unlimited findings; on larger repos this risks output truncation (~50 files/issues, >8k output tokens) and inflated API cost.

**LOW · quick-win** — Unpinned CI dependency
`.github/workflows/lint.yml:19`
`pip install PyYAML` has no version pin; a breaking release would silently break CI.

### Reliability (operator + QA)

*"Fully tested — as long as 'tested' means we checked the file has a colon in it."*

**MED · medium** — No execution/integration tests
`.github/workflows/lint.yml`
CI only runs frontmatter validation (`scripts/lint_frontmatter.py`); nothing verifies the skill actually runs or produces a well-formed report.

**LOW · quick-win** — Frontmatter split assumes Unix newlines
`scripts/lint_frontmatter.py:26`
The split on `---\n` can fail on CRLF checkouts where universal-newline translation is bypassed.

## Product panel

### Product & market *(merged)*

*"The moat is 'we wrote good prompts.' Anyone with a text editor is already in the castle."*

**MED · strategic** — No technical moat
`README.md`
As the README admits, a prompt-based skill repo has no technical moat; the value is entirely curation, refinement, and community adoption.

**LOW · —** — Resist feature creep
—
Avoid auto-fixing, code formatting, or language-specific prompt profiles. Keep the tool a high-level advisory review.

### Experience *(merged)*

*"Congratulations, the report is now fifty items long. Prioritizing them is your job, apparently."*

**HIGH · quick-win** — Prioritization burden shifted to user
`council/SKILL.md:22`
Without caps, the user must manually filter a potentially massive list, turning an expert panel into a noisy, text-heavy linter.

**LOW · quick-win** — Report pollutes workspace root
`council/SKILL.md:66`
Writing `REVIEW_<date>.md` to repo root clutters the workspace; a sub-folder (e.g. `.claude/reviews/`) would be tidier.

### Compliance reviewer

*"We ship your proprietary source to a third-party API and mention it precisely nowhere."*

**HIGH · quick-win** — No data-privacy warning
`council/SKILL.md:18`
The tool reads the target repo and transmits its contents to the LLM API; for proprietary or regulated code this may violate privacy policies (GDPR, SOC2), and the README warns of none of it.

### The Critic (no filter)

We've built a CI pipeline to lint the configuration file of a tool that does absolutely nothing but read files and output markdown. By removing the finding limits, we've transformed what was a focused, high-level advisory board into an expensive, wordy linter. The council no longer curates its feedback; it just vomits every minor observation it can find into a file, inflating the user's token bill and wasting their time. If we wanted a tool that lists fifty minor styling issues, we'd use ESLint for free, not a multi-million-parameter LLM that charges per token. Decide whether the council is an executive board or a noisy junior developer.
